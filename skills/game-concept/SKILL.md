# 游戏概念设计

决定这部小说适合变成什么体验。读取 [concept-method.md](references/concept-method.md)，输入为
`SOURCE_BIBLE.md` 与 `PRODUCT_BRIEF.md`。

产物语言由 `PRODUCT_BRIEF.md` 锁定；未锁定时跟随对话语言，不默认产出中文。

## 从原作形成方向

三个方向都从来源中选择值得玩家亲自经历的矛盾。每个方向写出一份自由描述的体验档案：

- **主要承载**：连续场景、对白、观察、空间行动、战斗、经营、探索或其他实际体验；
- **玩家参与**：玩家持续理解、表达、选择或执行什么；
- **剧情职责**：人物、关系、知识差、证词、物件与情节怎样推进；
- **系统职责**：规则、资源、空间和反馈怎样支持当前体验；
- **世界回应**：玩家影响怎样进入后续场景、人物行动、可知信息、规则条件或结局。

叙事主导、混合型、系统主导可以作为检查视角，帮助判断主要承载层和支持层。选定方向以具体体验
档案交接，让原作材料和玩家参与方式决定最终结构。

## 参考作品

选择真正解决过相近设计问题的参考作品，联网核实会影响判断的玩法、平台、受众和当前版本事实。
数量跟随问题复杂度；一个准确参考可以支撑一个明确原则，多项互相独立的问题可以各选参考。

每个参考记录：

- 它解决了什么问题；
- 哪个可观察设计证明这条原则成立；
- 这条原则如何服务当前小说的剧情、人物或规则；
- 当前原型采用到什么范围。

成熟类型语法适合验证动作、循环或关卡时，说明共有动词和结构。场景组织、人物回响、信息控制、
表演和分支也可以从互动小说、视觉小说、叙事冒险、桌面角色扮演、戏剧或影视中提炼。

## 生成三个方向

三个方向继承 brief 已锁定的平台、语言、玩家边界、分级与范围，并在玩家参与、所取原作段落、
主要承载或关键因果上形成实质差异。每个方向写清：

1. 产品定位、玩家身份和体验档案；
2. 选取的原作阶段、人物关系或冲突；
3. 玩家持续参与的方式；
4. 三条体验支柱，各配一个可观察试玩证据；
5. 原作中的剧情、人物目标或世界规则如何变成玩家可介入的因果；
6. 体验怎样推进，玩家在过程中知道什么、能做什么、人物和世界怎样变化；
7. 一个代表性介入时刻及其后续区别；
8. 一张能同时看出人物、处境和玩家参与方式的实际游戏画面；
9. 10–30 分钟最小验证切片、最大未知和观察问题。

## 选择方向

从以下方面比较三个方向：

- **原作保真**：来源中的人物意志、关系、冲突或规则进入了体验因果；
- **玩家能动性**：玩家理解信息、表明立场或采取行动后，世界给出可辨认的回应；
- **人物表现**：主要人物拥有自己的目标、知识、声口和行动能力；
- **体验连贯性**：场景或关卡之间存在清楚的前因后果；
- **范围可信度**：首个原型能完整走到一个设计结果；
- **文化与语言**：表达保留原作语境，并适合目标玩家阅读和理解。

推荐方向直接说明关键取舍和最大不确定性。`director` 模式把三个方向与推荐交给用户选择；其他
模式选择最能证明原作价值的方向继续。

## 输出

生成一个 `concepts/CONCEPT.md`，包含：

1. 产品定位与选定的 `experienceProfile`；
2. 原作价值与玩家参与方式；
3. 参考原则及核实状态；
4. 三个候选方向；
5. 比较与选定方向；
6. 选定方向的体验支柱、关键因果与招牌场面；
7. 最小验证切片、观察问题和开放问题；
8. 需要补回 `SOURCE_BIBLE.md` 的选定段落事实。

概念决定体验结构和关键取舍。具体场景、数值、关卡脚本和实现方案交给后续阶段。
