# 需求 intake：先形成改编假设

intake 先读原作，再起草一页产品方向。普通空白记录为工作假设；会改变产品形态、内容安全、授权、
平台或投入的选择交给用户裁决。

## 默认动作

1. 速读到足以判断语言、题材、主要人物、核心冲突、情绪内核、时代设定和内容尺度；
2. 摘出原作最值得玩家亲自介入的三项价值；
3. 提出 2–3 种玩家参与假设，说明玩家身份、持续参与和世界回应；
4. 推荐平台、目标交付运行时、界面语言、画风和完成度；
5. 标记成人内容、真实人物、未成年人、版权、外部服务和不可逆制作投入；
6. 形成完整草案，并将高风险分叉集中为少量用户问题。

参与假设为来源拆解和概念比较提供起点。选定概念随后写出正式 `experienceProfile`。

`quick` 默认 `assuranceProfile: smoke`。交给他人试玩或指定设备验收时采用 `delivery`，面向最终
用户的候选采用 `release`。

## 玩家参与假设

从原作价值出发描述玩家可能怎样进入作品：

- 观察人物、现场、物件和证词；
- 追问、表达、承诺、隐瞒或公开立场；
- 在空间中调查、行动、保护、追逐或离开；
- 使用原作已有的能力、职业、规则、资源或社会关系；
- 承担关键决定，并在后续人物行动、场景、可知信息、规则条件或结局中看到影响。

每个假设说明保留了原作什么、玩家如何感知影响、首个原型准备验证什么。叙事主导、混合型和系统
主导可作为概念阶段的检查视角，帮助发现场景、人物与规则分别承担多少体验。

## 产品框架

`PRODUCT_BRIEF.md` 用以下维度形成草案：

| 维度 | 最小内容 |
|---|---|
| 原作价值 | 核心剧情、人物、关系、规则和情绪 |
| 参与假设 | 2–3 种玩家身份、持续参与与世界回应 |
| 类型与参考 | 当前设计问题、参考作品与采用原则 |
| 时长与结构 | 验证切片时长、可能的场景或关卡结构、长期形态 |
| 平台与运行 | 交付物、引擎、目标运行时、显示、输入和性能预算 |
| 市场与语言 | 目标玩家、界面语言、文化语境 |
| 美术与完成度 | 画风、`targetFinish`、焦点资产和投入范围 |
| 内容尺度 | 分级、成人内容和平台边界 |
| 玩家结构 | 单人、多人、异步或实时 |
| 发行定位 | 买断、免费或 N/A，以及会影响体验的部分 |

另列 `assuranceProfile`、明确范围、授权与合规边界、工作假设和用户裁决项。

## 参考作品

先写当前需要解决的设计问题，再寻找已经处理过相近问题的作品。参考可以来自游戏、互动小说、
视觉小说、戏剧、影视或桌面角色扮演。联网核实会影响真实决定的玩法、平台、许可证、渠道和服务
事实。

需要候选作品、平台和画风索引时读取
[intake-benchmark-reference.md](intake-benchmark-reference.md)，再根据当前问题核实相关条目。选择生产
引擎与目标运行时需要进一步比较时，读取
[intake-engine-reference.md](intake-engine-reference.md)，并用当前官方资料核实版本与导出能力。

## 输出

`PRODUCT_BRIEF.md` 一页写清原作优先级、参与假设与产品边界。用户裁决项处理完成后进入来源拆解；
工作假设随证据更新。正式体验档案由概念阶段在完整 `SOURCE_BIBLE.md` 基础上选定。
